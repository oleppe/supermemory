## Spacing Scale

Vuetify's built-in spacing system uses a 4px base unit. Declared values used in this phase:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps within buttons, inline padding (`gap-x-1`) |
| sm | 8px | Compact element spacing (`mb-2`, `pa-2`) |
| md | 16px | Default element spacing (`pa-4`, `mb-4`) |
| lg | 24px | Card internal padding (`pa-6`), section gaps (`mb-6`) |
| xl | 32px | Layout section breaks (`mt-8`) |
| 2xl | 48px | Major section separation (`mt-12`) |
| 3xl | 64px | Page-level spacing (`mt-16` — auth illustration top margin) |

Exceptions:
- Auth card uses `pa-6` (24px) for internal padding — matches existing Vuexy auth page pattern
- Auth illustration uses `padding-inline: 6.25rem` (100px) — inherited from existing template, not a standard token
- Form field gap: 16px vertical between fields (Vuetify `VRow` default gutter)

**Source:** Vuetify spacing utilities already used throughout the codebase (`resources/ts/pages/login.vue`, `resources/ts/layouts/`).

## Interaction Contracts

### Login Flow
1. User lands on `/login` → sees centered card with "Login" tab active
2. User fills email + password → inline validation on blur (Vuetify `:rules`)
3. User clicks "Login" → button shows `:loading` spinner, form disabled
4. On success → redirect to `?redirect=` param or `/` (welcome dashboard)
5. On failure → inline error below form: "Invalid credentials" (from backend 401 response)

### Register Flow
1. User clicks "Register" tab → `VWindow` slides to register form
2. User fills email + password → same validation rules as login
3. User clicks "Register" → button shows `:loading` spinner
4. On success → auto-logged in (backend creates session), same redirect as login
5. On failure → inline error (e.g., "The Email has already been taken" from backend 422)

### Session Persistence
1. On app mount → `GET /sanctum/csrf-cookie` → `GET /api/auth/me`
2. If 200 → user is authenticated, render app shell
3. If 401 → redirect to `/login?redirect=/intended-path`
4. Browser refresh → same mount check, session cookie auto-sent

### Logout
1. User clicks avatar → dropdown opens
2. User clicks "Logout" → `POST /api/auth/logout`
3. On success → redirect to `/login` (full page reload via `window.location.href` to clear all client state)

### Route Guard
1. Unauthenticated user navigates to `/` or any protected route
2. `beforeEach` guard fires → `authStore.isAuthenticated` is false
3. Redirect to `/login?redirect=/full-path-they-wanted`
4. After login → redirect back to captured path

## Form Validation Rules

| Field | Rules | Source |
|-------|-------|--------|
| Email (login) | `requiredValidator`, `emailValidator` | `@core/utils/validators` |
| Password (login) | `requiredValidator` | `@core/utils/validators` |
| Email (register) | `requiredValidator`, `emailValidator` | `@core/utils/validators` |
| Password (register) | `requiredValidator`, custom `minLength(3)` | Backend requires `min:3` — do NOT use `passwordValidator` (requires 8+ chars with complexity) |

**Critical:** The existing `passwordValidator` in `@core/utils/validators.ts` requires uppercase + lowercase + digit + special char + 8 chars minimum. The backend `AuthController` only requires `min:3`. Using the existing validator would reject valid passwords. Define a simple inline rule: `(v: string) => v.length >= 3 || 'Password must be at least 3 characters'`.

## Layout Specifications

### Auth Page (`/login`)
- **Layout:** `blank` (no nav bar, no footer)
- **Structure:** Centered `VCard` (max-width 450px) on `bg-surface` background
- **Card padding:** `pa-6` (24px)
- **Card content:** Logo + title (centered), VTabs (grow), VWindow with forms
- **Responsive:** Full-width card on mobile, centered on desktop
- **Background:** `bg-surface` (matches existing `auth-wrapper` pattern)

### App Shell (authenticated pages)
- **Layout:** `DefaultLayoutWithHorizontalNav`
- **Nav bar:** Logo + title (left), ThemeSwitcher + UserProfile dropdown (right)
- **Nav items:** Empty array for Phase 1 (no feature links yet — D-05)
- **Content width:** `ContentWidth.Boxed` (from themeConfig)
- **Footer:** Static footer (from themeConfig)

### Welcome Dashboard (`/`)
- **Layout:** Inside app shell (horizontal nav + footer visible)
- **Structure:** Single `VCard` with welcome message + two placeholder quick-action buttons
- **Quick actions:** "Upload Documents" and "View Documents" — `VBtn` with icons, non-functional placeholders
- **Cards:** Use `mb-6` spacing between cards (matches existing `index.vue` pattern)
