    **api.ts — complete rewrite (per D-01, AUTH-03):**

    Replace the entire file content. The current file reads `useCookie('accessToken')` and sets `Authorization: Bearer` header. This must be completely replaced with Sanctum SPA cookie auth:

    - Remove: `useCookie('accessToken')` and Bearer header logic
    - Add: `credentials: 'include'` to ofetch.create options (sends httpOnly cookies automatically)
    - Add: In `onRequest` hook, read `useCookie('XSRF-TOKEN').value` and set as `X-XSRF-TOKEN` header
    - Add: In `onRequest` hook, set `Accept: application/json` and `X-Requested-With: XMLHttpRequest` headers (Laravel AJAX detection)
    - Add: `onResponseError` hook — if `response.status === 401`, lazy-import `useAuthStore` and set `authStore.user = null` (clears auth state on 401)
    - Keep: `baseURL: import.meta.env.VITE_API_BASE_URL || '/api'`

    The lazy import in the 401 handler (`await import('@/stores/auth')`) avoids circular dependency at module initialization time — api.ts is imported by auth.ts, so auth.ts cannot be imported at the top of api.ts.

    **stores/auth.ts — new file (per D-02, AUTH-03):**

    Create `resources/ts/stores/auth.ts` following the composition API pattern from `@core/stores/config.ts`:

    - Import: `import { $api } from '@/utils/api'`
    - Define `User` interface with fields: `id: number`, `email: string`, `name: string`, `preferred_language: string | null`, `is_admin: boolean` (matches AuthController `authPayload()` response shape)
    - Export `useAuthStore = defineStore('auth', () => { ... })`
    - State: `user = ref<User | null>(null)`, `isLoading = ref(false)`
    - Computed: `isAuthenticated = computed(() => user.value !== null)`
    - `fetchUser()`: try/catch wrapping `$api('/auth/me')`, sets `user.value = response.user` on success, `user.value = null` on catch. Set isLoading true/false around the call.
    - `login(email, password)`: set isLoading, call `$api('/auth/login', { method: 'POST', body: { email, password } })`, set `user.value = response.user`
    - `register(email, password)`: set isLoading, call `$api('/auth/register', { method: 'POST', body: { email, password } })`, set `user.value = response.user`
    - `logout()`: call `$api('/auth/logout', { method: 'POST' })` in try/finally, set `user.value = null` in finally
    - Return: `{ user, isLoading, isAuthenticated, fetchUser, login, register, logout }`

    **Key conventions:**
    - Two-space indentation, no semicolons (project convention)
    - `ref`, `computed`, `defineStore` are auto-imported — do NOT import them explicitly
    - `useCookie` is auto-imported from @vueuse/core

      const authStore = useAuthStore()

      if (to.meta.public)

      if (!authStore.isAuthenticated) {
        return {
          path: '/login',

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| api.ts → Backend | API client sends credentials; must include CSRF token for state-changing requests |
| Router guard → Auth store | Guard trusts auth store state; store must be initialized before first navigation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | CSRF on API requests | mitigate | api.ts reads XSRF-TOKEN cookie and sets X-XSRF-TOKEN header on every request. CSRF cookie fetched at app mount via /sanctum/csrf-cookie before any mutating request |
| T-02-02 | Information Disclosure | Auth state in client | accept | Auth store holds user object in memory only (not persisted to localStorage). On refresh, state is re-derived from server via fetchUser(). No sensitive data stored client-side |
| T-02-03 | Spoofing | Router guard bypass | mitigate | Guard checks authStore.isAuthenticated which depends on server-validated user from /api/auth/me. Client-side guard is UX convenience; server-side auth:sanctum middleware is the real enforcement |
| T-02-04 | Elevation of Privilege | 401 response handling | mitigate | api.ts onResponseError clears authStore.user on 401, preventing stale auth state from granting access to protected UI after session expires |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in this phase |
</threat_model>
