<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Login form → Auth store | User input (email/password) flows through Vuetify validation before reaching auth store |
| UserProfile → Logout | Logout action requires authenticated session; server-side validation is the real enforcement |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | Login/Register form input | mitigate | Vuetify `:rules` provide client-side validation (required, email format, min password length). Server-side validation in AuthController enforces rules independently — client validation is UX convenience only |
| T-03-02 | Information Disclosure | Error messages | mitigate | Server error messages displayed via VAlert are limited to "Invalid credentials" (generic) — no user enumeration. Backend returns 401 for both wrong email and wrong password |
| T-03-03 | Spoofing | Redirect after login | mitigate | `route.query.redirect` is passed to `router.push()` which only navigates within the SPA — cannot redirect to external URLs. Vue Router validates route existence before navigation |
| T-03-04 | Denial of Service | Repeated login attempts | accept | Backend `throttle:auth` middleware rate-limits login attempts (handled in Plan 01). Frontend has no additional rate limiting — server-side is authoritative |
| T-03-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in this phase |
</threat_model>
