<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → API | SPA sends credentials over HTTP; session cookie returned |
| Session cookie → Server | httpOnly cookie auto-sent by browser; server validates session |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Information Disclosure | Session cookie | mitigate | httpOnly cookie via Sanctum session driver — JS cannot read cookie value. Verified in `EnsureFrontendRequestsAreStateful::configureSecureCookieSessions()` |
| T-01-02 | Tampering | Login/Register POST | mitigate | CSRF protection via `/sanctum/csrf-cookie` endpoint + `X-XSRF-TOKEN` header + `ValidateCsrfToken` middleware (configured in `config/sanctum.php` line 81) |
| T-01-03 | Spoofing | Session after login | mitigate | `$request->session()->regenerate()` after login and register prevents session fixation attacks |
| T-01-04 | Denial of Service | Login endpoint | mitigate | `throttle:auth` middleware already applied to `/api/auth/login` and `/api/auth/register` routes (routes/api.php lines 32, 35) |
| T-01-05 | Information Disclosure | Session hijacking | accept | SameSite=Lax set by Laravel session config (config/session.php). HTTPS enforcement via SESSION_SECURE_COOKIE is a deployment concern, not code concern |
| T-01-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in this phase — all libraries already in composer.json/package.json |
</threat_model>
